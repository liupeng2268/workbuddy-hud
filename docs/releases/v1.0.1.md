# v1.0.1

修复两处统计正确性缺陷。它们不会让程序崩溃，但会让显示的数字悄悄偏离真实值——这类问题比崩溃更难被发现，所以单独发一版。

## 修复

| 缺陷 | 表现 | 根因 |
|------|------|------|
| 增量读取丢记录 | 每批追加只统计到一部分，实时数字明显滞后 | 已消费到的位置本来就在行首，读取时却仍按「首行是半行」丢弃，每批必丢第一条完整记录 |
| 历史口径重复计数 | 「全历史」的记录数与累计输出偏高，切换会话后继续累积 | 会话扫描也往历史计数器累加，历史扫描随后又从头读一遍同一批文件 |

实测对照：向 10 条记录的文件追加 1 条，修复前记录数仍是 10；修复后为 11。

## 其他变更

## 下载与校验

附件名为 `WorkBuddy-HUD.exe`（ASCII，避免中文文件名在部分下载工具里被截断）；程序自身名称仍是 `WorkBuddy悬浮窗.exe`，运行行为不受影响。

```
SHA256  69F542058FDCA228970C4A5936D72E1E9BE62E41932767886C2D58A0A12BED97
```

PowerShell 校验：

```powershell
Get-FileHash .\WorkBuddy-HUD.exe -Algorithm SHA256
```

本版未做代码签名，首次运行若出现 SmartScreen 提示属预期，可点「更多信息 → 仍要运行」。

## 已知限制

- 文件被截断或重写后重新读取，历史口径仍会二次计数（见 `docs/adr/0001-双口径记账权归属.md`）
- 历史口径的更新周期是 3.2 秒，数字会比会话口径滞后一拍
- 运行期新出现的、超过 4 MB 的日志只回溯读取末尾 4 MB
- 停止生成后，速率会沿旧值继续显示至多 60 秒
