# WorkBuddy 悬浮窗 · 使用说明

在桌面上常驻一个置顶小窗，实时显示 WorkBuddy 的缓存命中率与生成速率。
支持**当前会话 / 全历史**两种命中率口径，以及 7 种可切换的附加指标。

---

## 一、启动

| 方式 | 文件 | 适用场景 |
|------|------|----------|
| **推荐** | `dist\WorkBuddy悬浮窗.exe` | 双击即可，**不依赖 Python 环境与文件关联** |
| 备用 | `启动.bat` | 需要 Python 在 PATH 中 |
| 开发调试 | `WorkBuddy悬浮窗.pyw` | 需要 `.pyw` 文件关联正常 |

> **为什么双击 `.pyw` 没反应？**
> 本机 `.pyw` 文件关联已缺失（注册表 `HKCU` 与 `HKLM` 下均无 `Python.NoConFile` 项），双击时 Windows 不知道用哪个程序打开，因此不会启动任何进程。改用 exe 即可。

启动后窗口出现在**屏幕右下角**，首次约 1 秒出数。

## 二、操作

| 操作 | 效果 |
|------|------|
| 按住窗口拖动 | 移动到任意位置 |
| 右键 → **设置…** | 打开设置窗口，调整显示内容 |
| 右键 → 刷新 | 立即重新读取 |
| 右键 → 复制快照 | 把当前全部指标复制到剪贴板 |
| 右键 → 退出 | 关闭程序 |

## 三、设置项

设置窗口通过**右键 → 设置…**打开，保存后立即生效，并写入同目录 `设置.json`。

| 设置项 | 可选值 | 默认 |
|--------|--------|------|
| **命中率口径** | 当前会话 / 全历史 | 当前会话 |
| **第三行显示** | 会话输出 / 全历史输出 / 上下文用量 / 请求次数 / 会话时长 / 模型名称 / 未命中 token / 隐藏 | 会话输出 |
| **刷新间隔** | 0.5 秒 / 1 秒 / 2 秒 / 5 秒 | 1 秒 |
| **窗口透明度** | 100% / 95% / 90% / 85% / 80% | 100% |

### 两种命中率口径的取舍

| 口径 | 显示 | 特点 | 适合 |
|------|------|------|------|
| **当前会话** | `命中率 97.8%` | 只统计当前对话（含其 subagents），随对话实时变化 | 想知道「这次对话缓存打得好不好」 |
| **全历史** | `全历史 96.5%` | 全部 324 个日志、2.2 万条记录的累计加权值 | 想知道「长期平均缓存效率」 |

实测参考：当前会话通常 97%~98%，全历史稳定在 96.4% 附近。两者不同时显示，避免窗口拥挤。

### 第三行各指标含义

| 选项 | 示例 | 含义 |
|------|------|------|
| 会话输出 | `会话 268.8K tok · 317 条` | 当前会话累计输出 token 与 usage 记录数 |
| 全历史输出 | `历史 22.7M tok · 22318 条` | 全部历史累计（首次需 2~3 秒统计，期间显示「历史统计中…」） |
| 上下文用量 | `上下文 306.9K tok` | 最近一次请求的 prompt token 数，即当前上下文长度 |
| 请求次数 | `请求 317 次` | 当前会话的 API 调用次数 |
| 会话时长 | `时长 6.7 时` | 当前会话从首条记录到最新记录的时间跨度 |
| 模型名称 | `模型 deepseek-v4.1-flash` | 当前会话使用的模型 |
| 未命中 token | `未命中 993.9K tok` | 缓存未命中的真实输入量，反映实际消耗 |
| 隐藏 | — | 只显示前两行 |

## 四、界面说明

```
命中率 97.8%              ← 第一行：命中率（口径由设置决定），≥60% 绿 / 30~60% 黄 / <30% 红
143.5 tok/s               ← 第二行：最近 60 秒生成吞吐
会话 268.8K tok · 317 条   ← 第三行：由设置选择，默认显示会话输出
```

**速率口径**：最近 60 秒窗口内 `completion_tokens` 之和 ÷ 窗口跨度，是**端到端吞吐**，含模型思考与工具等待时间。空闲时无样本则显示 `--`。

## 五、数据来源与隐私

- 只读取本机 `C:\Users\22680\.workbuddy\projects\` 下的会话日志
- **纯只读**，不修改、不移动、不删除
- **零网络请求**，不填 API Key，不上传任何数据
- 只解析 token 计数字段，不读取对话正文

## 六、卸载

删除整个 `WorkBuddy悬浮窗` 文件夹即可，无注册表残留。

## 七、常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 双击 `.pyw` 没反应 | 本机 `.pyw` 关联缺失，改用 `dist\WorkBuddy悬浮窗.exe` |
| 双击 exe 没反应 | 查看 exe 同目录 `运行日志.txt`；若不存在，可能被杀毒软件拦截 |
| 切到「全历史」显示统计中 | 首次需 2~3 秒扫完全部历史，之后即稳定 |
| 数值突然归零或跳变 | 切换了会话，正在重新统计，属正常 |
| 速率一直是 `--` | 最近 60 秒没有生成活动 |
| 设置改了没生效 | 确认点了「保存」；设置写入 exe 同目录 `设置.json` |
| 想恢复默认 | 删除 `设置.json` 后重启 |
| 想开机自启 | 把 exe 的快捷方式放入 `shell:startup` 目录 |

| 目录 | 内容 | 可否删除 |

| `过程脚本/` | 开发期的探针、测量、截图与验证脚本 | 可，不影响运行 |

| `_临时/` | PyInstaller 缓存、调试截图、历史版本备份 | 可，重新打包会重建 |

## 九、技术要点

- 纯 Python 标准库实现（`tkinter` + `json` + `threading`），无第三方依赖
- exe 由 PyInstaller 打包（单文件、无控制台，约 12 MB）
- 双口径统计各有独立 offset 表：会话口径只读当前会话（1 秒内），历史口径读全部（2~3 秒，之后每 3.2 秒增量）
- `snapshot()` 只做内存汇总，不触发磁盘 IO，不阻塞界面
- 实测数据规模：324 个日志文件 / 354 MB / 22,318 条 usage 记录
